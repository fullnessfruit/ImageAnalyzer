# 샘플 정답

[`labels.json`](labels.json)은 `sample/` 이미지의 파일별 정답이다. `people`과 `characters`는 이미지에 보인다고 확인한 대상이며, 이름의 중복 없이 한 이미지에 묶었다. `subjectNotes`는 뒷모습, 옆얼굴, 이미지 내 위치처럼 대상별로 필요한 설명이다. 이 기록은 모델의 현재 출력이 아니다.

`ocr`는 실제로 적혀 있고 회귀 검사에서 찾아야 하는 검색어다. `optionalOcr`는 적혀 있지만 현행 인식 실패를 허용하고, `absentOcr`는 **적혀 있지 않은** 검색어라 검출되면 실패다. `ocrText`는 검색어와 다른 실제 표기 또는 줄 배치를 설명한다. `imageNotes`는 파일 전체의 매체·촬영 상황·판정 범위를, `subjectNotes`는 대상별 뒷모습·옆얼굴·위치를 설명한다. `faceChecks`는 기존 얼굴 회귀 검사의 필수 성공 대상이며, `people`에 기록된 모든 사람이 곧바로 얼굴 검사의 필수 성공 대상이 되는 것은 아니다. 얼굴이 거의 보이지 않는 신체 판정 시험 이미지는 `faceCheck: "skip"`이다. 캐릭터 라벨도 실제 등장 여부를 기록하며, 현재 검사기는 누락을 진단 출력으로 남긴다. `absentNames`는 브로커의 이름별 `found` 결과에 나오면 안 되는 등록 이름이다. 같은 이름의 캐릭터와 의상이 모두 있을 때 의상 매칭만으로 캐릭터 이름이 검출되지 않는지도 검사한다. 의상 매칭 자체는 종류가 붙은 `matches`에 남긴다.

열 이미지의 `absent: "allCatalogedSubjects"`는 `subjectCatalog.people`과 `subjectCatalog.characters`에 **이름이 전부 적힌 대상 모두**가 그 이미지에 없다는 뜻이다. 목록에는 QMa 이미지에서 OCR 텍스트로만 라벨링한 相良茉優·内田秀도 포함한다. 다른 미등록 인물·캐릭터나 텍스트까지 없다는 뜻은 아니다. `unlabeledImages`는 파일은 있으나 확인된 정답이 없는 이미지다. 현재는 82장 전부에 확인한 정보가 있지만, **각 항목은 적힌 사실만 보증하는 부분 라벨**이다. 이름이 없다는 이유만으로 그 인물이 부재한다고 해석해서는 안 된다.

과거 Claude 세션 기록 2개와 현재 세션의 사용자 설명·실험 기록을 대조하고 실제 이미지를 확인했다. `HT8Ro88agAAdTWa.jpg`는 사용자가 大西亜玖璃라고 지정한 뒷모습 평가 이미지다. `c02.png`·`c02a.png`·`c02s.png`와 `chara_01_*`·`face_01_*`는 上原歩夢 일러스트이고, `c02cv.png`는 담당 성우 大西亜玖璃의 실사 얼굴이다. `G0e2w21aEAA6Ndl.png`·`HFEmpdcbAAAfbRb.jpg`와 위 캐릭터 참조 그림은 등록 갤러리에도 같은 파일이 있어 **독립 성능 평가에 쓰면 안 된다**. 과거 모델이 낸 이름만으로 정답을 만들지 않았고, 그 밖의 추가 사진은 실제 이미지의 인물·글자·위치를 확인해 기록했다. 확인하지 않은 다른 등장 인물의 신원은 비워 두었다.

`ocr-replay/`는 과거 운영 이미지의 OCR 속도·정확도 비교용 사본이다. `bench.cjs`의 검색어 목록은 검사 입력일 뿐 정답이 아니므로, 각 파일의 실제 표기와 부재 여부를 별도로 `images`에 적었다. 일부는 검색어가 전혀 없는 장면이고 일부는 작은 출연자 명단만 포함한다.

`trainingMedia`의 세 경로는 `sample/` 밖의 上原歩夢 갤러리 원본이다. 각각 인형 사진, 굿즈의 데포르메 일러스트, 피규어 사진이라는 매체 차이를 남겼다. 나머지 갤러리 원본까지 이 샘플 파일의 정답으로 간주하지 않는다.

上原歩夢 갤러리를 기존 일러스트 4장, 추가 일러스트 포함 7장, 인형·데포르메 굿즈·피규어 포함 10장으로 나눠 독립 샘플 8장과 명시적 부재 샘플 7장을 비교했다. 세 구성 모두 정면 등 식별 가능한 7장은 검출하고, `kv01.jpg`의 뒷모습은 놓쳤으며, 부재 7장은 전부 기각했다. 다만 10장 구성에서 부재 샘플 최고 점수가 0.737로 7장 구성의 0.704보다 높았다. 특수 매체 참조가 이 표본에서 추가 검출을 만들지는 못했으므로 이 세 종류의 효용과 오검출 위험은 실제 인형·굿즈·피규어 질의 이미지로 추가 검증해야 한다.

`XJt75abr9IYTRIQa.jpeg`에는 `Nijigasaki`가 휘어진 작은 로고에 적혀 있지만 현재 OCR은 놓친다. 원본 분석 점수는 0.022, 더 높은 검출 스케일은 0.026, 로고 부분을 분리해 3배 확대한 실험은 0.022로 모두 판정 기준 0.5에 못 미쳤다. 이 단어를 `ocr` 필수 항목에 남겨 향후 개선 때 누락을 확인한다. 같은 이미지의 `虹ヶ咲`는 현재 검출된다.

`HUp3BAfbkAE98jj.jpg` 카드의 영문 이름 9개는 세로 방향으로 회전해 적혀 있으며 현재 OCR 점수 0.006~0.012로 모두 놓친다. `HUvY-rIbsAAA4Fk.jpg`의 작고 장식적인 `μ's`도 0.045로 놓친다. 두 이미지의 OCR 라벨은 실제 표기이므로 필수 항목에 남긴다. 이 두 이미지에서 `npm run samples:labeled`가 실패하는 것은 현재 OCR의 알려진 누락이며, `absentNames`에 따른 아유무 신원 오검출 검사는 별도로 통과한다. 다섯 이미지의 의상 유사 매칭은 아직 남아 있어 검사 출력에 함께 기록한다.

`npm run samples:labels`는 이름 참조와 실제 이미지 목록을 검사한다. `npm run samples:labeled -- <파일명>`은 지정한 이미지의 분석 결과를 기록된 얼굴·OCR 정답과 비교한다. 매체와 뒷모습 라벨은 존재 정보이지 현재 모델의 성공 보증이 아니다.
